# Security Policy

SuperTile is developed as if it were a product placed on the EU market under
the **Cyber Resilience Act (Regulation (EU) 2024/2847)**. This document is the
coordinated vulnerability disclosure (CVD) policy required by CRA Annex I,
Part II. Process and conformance detail lives in
[docs/compliance/EU-CRA.md](docs/compliance/EU-CRA.md).

## Supported versions

| Version | Supported | Security fixes until |
|---|---|---|
| 0.28.x | ✅ current | until superseded by 0.29.x |
| < 0.28 | ❌ | superseded — upgrade to the current release |

Pre-1.0, only the current minor series is supported. Fixes are published as a
new patch release rather than backported: there is no installed base on an older
series that could not upgrade, and maintaining branches nobody is running would
be effort spent on nothing.

The **support period** for SuperTile is **five years** from the date of each
release, in line with CRA Article 13(8). Security updates are published as new
patch releases and are announced in [CHANGELOG.md](CHANGELOG.md) under
**[Security]**.

## Reporting a vulnerability

**Please do not open a public issue for a security problem.**

Report privately through either channel:

1. **GitHub Security Advisories** — preferred.
   [Report a vulnerability](https://github.com/andreaswiren/supertile/security/advisories/new)
2. **Email** — andreas.wiren@gmail.com with `[SuperTile Security]` in the
   subject.

Please include, as far as you can:

- affected version and Windows build,
- a description of the issue and its impact,
- reproduction steps or a proof of concept,
- any suggested mitigation.

## What to expect

| Stage | Target |
|---|---|
| Acknowledgement of your report | **72 hours** |
| Initial triage and severity assessment (CVSS v3.1) | **7 days** |
| Fix or documented mitigation for critical issues | **30 days** |
| Fix or documented mitigation for high/medium issues | **90 days** |
| Public advisory | at patch release, or 90 days, whichever is first |

We will keep you updated at each stage, credit you in the advisory unless you
prefer otherwise, and coordinate the disclosure date with you.

### Actively exploited vulnerabilities

Consistent with CRA Article 14, an actively exploited vulnerability in a
released version will be reported to the relevant CSIRT and to ENISA via the
single reporting platform within **24 hours** of becoming aware of it, with a
follow-up notification within **72 hours** and a final report within
**14 days**.

## Scope

**In scope**

- The `supertile.exe` binary and everything under `src/`
- The configuration and geometry-memory file formats
- The build and release pipeline in `.github/workflows/`
- Dependencies as declared in `Cargo.lock` and the
  [SBOM](docs/compliance/sbom.cdx.json)

**Out of scope**

- Vulnerabilities in Windows itself — report those to MSRC
- Attacks requiring administrator rights already on the machine, or physical
  access to an unlocked session
- Social engineering, or reports generated by a scanner without a demonstrated
  impact on SuperTile

## Security properties

The threat model is documented in full at
[docs/compliance/threat-model.md](docs/compliance/threat-model.md). In summary,
SuperTile is designed so that:

- It runs entirely as the **current user** and requires no elevation. It does
  not install a service, a driver or a scheduled task.
- It makes **one kind of network connection, and only when you ask for it**: an
  HTTPS request to `api.github.com` to see whether a newer release exists. It is
  **off by default** and is the only outbound traffic the program can produce.
  There is no telemetry, no analytics, no crash reporting, and nothing is ever
  downloaded or installed automatically — the check reads a version number and a
  URL, and reports them.

  Anything else leaving `supertile.exe` — any other host, or any traffic at all
  while update checks are disabled — should be reported as a vulnerability.

- **Ask Claude opens a URL; it does not send anything itself.** When the palette
  hands a question to `https://claude.ai/new?q=…`, that request is made by your
  browser, under your session, and the question is visible in the address bar
  before it goes anywhere. SuperTile opens no connection of its own for it, and
  the question is never sent to Claude — the URL fills the composer and stops.
  The feature is off by default.

  What the request reveals to GitHub is what any HTTPS request reveals: your IP
  address, an approximate time, and a `User-Agent` naming this program and its
  version. Nothing about your windows, your machine or your configuration is
  sent, and no identifier is attached.
- It writes only to `%LOCALAPPDATA%\SuperTile\` and a single
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value when the user
  enables start-with-Windows. It never writes to `HKLM` or to `%PROGRAMFILES%`.
- All parsed input — the JSON configuration, the geometry store, saved split
  layouts, `.lnk` shortcut targets, window metadata read from other processes,
  and the JSON returned by GitHub — is treated as **untrusted** and validated
  before use. The release URL from GitHub is checked to be under
  `https://github.com/andreaswiren/supertile/` before it can be opened, because
  it would otherwise reach `ShellExecuteW` on a single click.
- The codebase contains no `unsafe` block that is not required for a Win32 FFI
  call, and each one carries a `// SAFETY:` comment stating the invariant it
  relies on. This is enforced in CI.

## Verifying a release

Each release publishes SHA-256 checksums and a CycloneDX SBOM. Verify with:

```powershell
Get-FileHash .\supertile.exe -Algorithm SHA256
```

and compare against `SHA256SUMS.txt` on the release page.
